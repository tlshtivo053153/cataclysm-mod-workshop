# check_mods.sh ルール追加計画（改訂版）

## 当初計画の批判分析

当初計画では「CORE.mdにcheck_mods.shの手順を追加すればよい」としていたが、以下5点の重大な見落としがあった。

### 問題1: validate.sh と check_mods.sh の根本的な違いの無視

| | validate.sh | check_mods.sh |
|---|---|---|
| 入力 | ディレクトリパス | mod_id（modinfo.json内のid） |
| 前提 | なし | `external/cdda/cataclysm-tiles` バイナリ + modが `external/cdda/mods/` に配置済み |
| 実行時間 | 1秒未満 | 最大30秒 |
| 検出範囲 | JSON構文エラーのみ | 依存解決・copy-from存在・必須フィールド・型不一致などCDDAエンジンレベルのエラー |

当初計画はこれらを「Level1→Level2」のリニアなステップとして単純化しすぎていた。実際には `validate.sh` は頻繁（編集のたび）に実行すべき軽量チェック、`check_mods.sh` はマイルストーン的な（ゲーム起動前の）重チェックである。

### 問題2: mod配置の前提ステップの欠落

`check_mods.sh` は `mod_id` を引数に取るが、modが `external/cdda/mods/` に存在していることが前提。modは `mods/<size>/<mod_name>/` に開発するため、`link_mod_for_test.sh` または `copy_mod_for_test.sh` で配置するステップが必要。当初計画はこの前提を完全に見落としていた。

### 問題3: mod_id とディレクトリ名の不一致リスク

`check_mods.sh` が受け取るのは `modinfo.json` 内の `"id"` フィールド。一方 `link_mod_for_test.sh` が作成するシンボリックリンク名はソースディレクトリのベース名。これらが一致するとは限らない。不一致ケースへの言及と対処法が必要。

### 問題4: CORE.md への過剰な情報追加

CORE.md は47行の簡潔な基本ルールであり「全モデル必読」の位置づけ。ここに配置手順・前提条件・エラー解釈などの詳細を含めると、CORE.mdの簡潔さを損なう。

### 問題5: 実行後のエラー調査フロー欠落

`check_mods.sh` は実行前に `config/debug.log` をクリアする。つまり実行後は `external/cdda/config/debug.log` の内容が全てそのセッションのエラーとなる。この debug.log の読み方（hints_basic.md にも既に言及あり）と `check_mods.sh` の連携が説明されていない。

## 改訂計画

### 1. CORE.md: 開発の進め方に1行追加（最小限の変更）

```diff
 ## 開発の進め方
 1. 実装前に必ず設計書（templates/design_template.md）を作成する
 2. external/cdda/data/json/ を参照してIDやフラグの正確な綴りを確認する
-3. 実装後は必ずJSONの構文チェックを行う（scripts/validate.sh）
+3. 実装後は必ずJSONの構文チェックを行う（scripts/validate.sh）
+4. validate.sh通過後、modを external/cdda/mods/ に配置しCDDA組み込みチェックを行う（scripts/check_mods.sh）。詳細は rules/verification.md 参照
```

### 2. 新規ファイル: `rules/verification.md`（検証ツール詳細マニュアル）

以下の構成で作成する：

```markdown
# 検証ツール

## Level1: JSON構文チェック（validate.sh）
（既存の説明を移行 or 参照）

## Level2自動: mod読み込みチェック（check_mods.sh）
- 概要
- 前提条件（CDDAバイナリ、mod配置）
- 完全な手順（5ステップ）
- mod_id確認方法
- 検出できるエラーとできないエラー
- debug.logの読み方
- 注意点（タイムアウト、パフォーマンス）

## mod配置（link_mod_for_test.sh / copy_mod_for_test.sh）
- symlink vs コピーの使い分け
```

### 3. hints_basic.md: recipeチェックリスト他への追記

- recipeチェックリストにcheck_mods.shの項を追加
- debug.logセクションにcheck_mods.sh後の確認手順を追記

### 4. design_template.md: テスト手順にcheck_mods.shを追加

```diff
 ### テスト手順
 1. validate.shでJSON構文チェック
 2. link_mod_for_test.shでCDDAに配置
 3. check_mods.shでmod読み込み確認
-4. CDDAを起動してmodを有効化
+4. CDDAを起動してLevel3確認
```
