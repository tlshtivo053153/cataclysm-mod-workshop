# 短期戦略的改善 実行計画

## 概要

クリティカル分析で指摘された「短期」4項目を実装する：
1. テストの作成（`common.py` + 全変換スクリプト）
2. CI/CD の導入（GitHub Actions）
3. `issue.md` の更新（古い内容を削除、現状に即した課題に差し替え）
4. シェルスクリプトに `set -euo pipefail` 追加（`validate.sh` のみ未設定）

| テスト対象 | テスト内容 |

| `process_directory` | 全ファイルに processor 適用、backup 有効／無効、processor が None を返すとスキップ |
| `process_file` | 単一ファイル処理、backup 有効／無効、processor が None を返すと False |

## 2. CI/CD の導入

### 2-1. `.github/workflows/ci.yml`

GitHub Actions ワークフローを作成（remote 未設定だが、push 時に即座に有効化できるよう準備）：

```yaml
name: CI

on:
  push:
    branches: [master]
  pull_request:
    branches: [master]

jobs:
  python:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install ruff black pytest
      - run: ruff check scripts/
      - run: black --check scripts/
      - run: python -m pytest scripts/tests/ -v

  shell:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: sudo apt-get install -y shellcheck
      - run: shellcheck scripts/*.sh
```

### 2-2. `.shellcheckrc`（必要な場合）

ShellCheck のチェック除外ルールを必要に応じて追加。現在のスクリプトは `shellcheck source=/dev/null` が1箇所 (`setup_venv.sh:17`) あるため、問題なし。

- 「ルール削除条件の未定義」 — 既に `cdda_mod_dev_plan.md` に閾値定義済み（解決済み）

- 「解決済み問題」セクション — Wilson信頼区間等、削除されたシステムに関する内容

- **`issue.md` の自己記述更新**: 「本ファイルも定期的に見直しが必要」というメタ注記

## 4. validate.sh に `set -euo pipefail` 追加

### 変更内容

```bash
#!/bin/bash
# validate.sh — mod内の全JSONファイルの構文チェック
set -euo pipefail   # ← この行を追加

MOD_DIR="${1:-.}"
```

### 副作用の確認

- `validate.sh` は `python3 -m json.tool` の終了コードを直接参照しておらず、独自の ERROR カウンタを使用しているため、`set -e` による早期終了のリスクは低い
- `while read` のパイプ問題は既にプロセス置換 `< <(...)` で回避済み

## 実装順序

```
1. validate.sh に set -euo pipefail 追加           (1ファイル、影響小)
2. scripts/tests/ ディレクトリ作成 + __init__.py
3. test_common.py 作成                              (最も基盤的なテスト)
4. test_convert_item_types.py 作成
5. test_add_activity_level.py 作成
6. test_convert_price.py 作成
7. test_remove_armor_bullet.py 作成
8. test_remove_invalid_fields.py 作成
9. pyproject.toml の testpaths 更新
10. pytest で全テスト実行 → パス確認
11. .github/workflows/ci.yml 作成
12. issue.md 更新
```
