# ルール追加計画: 変異カテゴリ実装 + check_mods.sh 同時実行禁止

## 概要

SUID/TURTLE/FORMICIDの変異カテゴリmod実装で得られた知見を既存ルールに追加し、`check_mods.sh` の同時実行禁止ルールを追加する。

## 変更ファイル一覧

flexcacheを自動クリアするよう変更。既に `debug.log` をクリアしているのに加え、`flexcache` も起動前に削除することでファイル変更検出による exit 1 を防止する。

### 2. `rules/patterns/mutation_category.md` (新規)

変異カテゴリ実装の包括的なパターンファイル。以下を含む：

- **概要**: 変異カテゴリmodとは何か、いつこのパターンを使うか
- **ファイル構成**: 7ファイルの標準構成と各ファイルの役割
- **各ファイルの実装テンプレート**:
  - `modinfo.json` — category: "mutation" 推奨
  - `mutation_category.json` — type: "mutation_category", vitamin/threshold_mut連携
  - `vitamin.json` — counter型, disease_excessでmutagen_effect強度制御
  - `mutagen_items.json` — `copy-from: mutagen_flavor` / `copy-from: iv_mutagen_flavor`
  - `mutagen_effects.json` — max_intensity: 3, base_mods + scaling_mods
  - `mutations.json` — 変異ツリー（ルート→中位→閾値後）の全構造
  - `extended_mutations.json` — `copy-from` + `extend` パターンで既存変異にカテゴリ追加
- **設計ルール**:
  - 閾値ゲート: `THRESH_*` は `valid: false, purifiable: false, threshold: true`
  - 閾値後変異: `threshreq`, `purifiable: false` 必須
  - 変異ツリー: `changes_to` で分岐、`prereqs` で親指定
  - 攻撃変異: `blocker_mutations` で他カテゴリと競合管理
  - 装備制限: `restricts_gear` + `destroys_gear: true`
  - エンチャント: mutation modifiers より modern enchantment system を使用
- **Vitaminシステムとの連携**: 閾値越えに十分なプライマー量（2200+）が必要な仕組み
- **注意点・よくあるミス**:
  - 閾値前変異が少なすぎるとプライマーが機能しない（1個では不十分、3個以上推奨）
  - `changes_to`/`cancels` で参照される既存変異にもカテゴリ追加が必要
  - `threshreq` を外せば閾値前変異に変更可能
  - `EATPOISON` 依存連鎖問題（WEAKSTOMACH→EATPOISON, VOMITOUS→EATPOISON, NAUSEA→VOMITOUS）
  - Vitamin `disease_excess` の閾値 `[2200, 2500]` が intensity 3 = プライマーレベル

### 3. `rules/common_errors.md` (追記)

`## よくあるエラー（変異・エンチャント関連）` セクションを追加：

```markdown
### mutation_type の不正な値
- **原因**: `types` フィールドに未定義の値を指定している
- **解決策**: 有効値は `external/cdda/data/json/mutations/mutation_type.json` に定義されたもののみ
- **よくある間違い**: `SMELL` → `SCENT`, `ATTACK` → `SECRETION`

### enchantment value の未定義エラー
- **原因**: enchantmentの `values` に存在しない value 名を指定している
- **解決策**: `external/cdda/data/json/` の enchantment 定義を確認する
- **よくある間違い**:
  - `PAIN_RESIST` は未定義 → `PAIN` + multiply: -0.25 で代用
  - `ARMOR_BALLISTIC`, `ARMOR_ACID` 等の旧防具フラグは enchantment では使えない

### comfort 条件の不正なtype
- **原因**: comfort フィールドの `condition.type` に無効な値を指定している
- **解決策**: 有効値は `terrain`, `field`, `vehicle`, `furniture`, `trait` のみ
- **よくある間違い**: `npc_following` → 存在しないtype。
```

### 4. `rules/verification.md` (追記)

以下の項目を `注意点` セクションに追加：

```markdown
### check_mods.sh の同時実行禁止
- **理由**: check_mods.sh は `external/cdda/config/debug.log` を同時にクリア・書き込みするため、並行実行するとログが破損する
- **ルール**: 複数modを検証する場合は **必ず逐次実行する**
  - 良い例: `bash scripts/check_mods.sh mod_a && bash scripts/check_mods.sh mod_b`
  - 悪い例: `bash scripts/check_mods.sh mod_a & bash scripts/check_mods.sh mod_b &`
```

## 補足: 今回の実施タスクで得た教訓メモ

以下の項目はルール化せず、planファイルにのみ記録する（個別事例または閾値判断に属するため）：

- `BEAK` のFORMICIDからの削除: テーマ不整合。実装前に `extend` 先の各変異がテーマに合致するか確認する習慣が必要
- `CLAWS` 差し替え: 同様にテーマ整合性の確認
- `EATPOISON` 依存連鎖の深さ: 変異依存ツリーを辿って `changes_to`/`prereqs` の連鎖を確認する習慣が必要
- `copy-from: mutagen_flavor` では `type: "ITEM", subtypes: ["COMESTIBLE"]` の明示が必要（abstractな親からは継承されない）
