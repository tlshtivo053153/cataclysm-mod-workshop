# レビュー指摘事項修正計画

## 概要

レビューで指摘された `version_diff.md` / `common_errors.md` への未反映変更、スクリプトの不備、文書整合性の問題を修正する。

---

## フェーズA: ドキュメント更新（`rules/`）

### A1. `rules/version_diff.md` に未反映の6項目を追記

作業ログで発見したが `version_diff.md` に記載されていない変更：

1. **special_attacks の無効化**
   - `RANGED_PULL`, `GRAB_DRAG`, `SHOCKSTORM`, `STRETCH_ATTACK`, `GRAB` 等が無効化
   - `monsters/` 配下の `special_attacks` 配列から該当値を削除

2. **overmap_terrain の see_cost 必須化**
   - `overmap_terrain` 型に `see_cost` フィールドが必須化
   - 有効値: `"none"`, `"low"`, `"medium"`, `"high"` 等

3. **EOC 条件の変更**
   - `compare_int` 条件が無効化
   - `target_params` 内の `search_range` が無効化

4. **rot_spawn 形式変更**
   - 配列形式 `{"monster": "zombie", "probability": 10}` → オブジェクト形式 `{"zombie": 10}`

5. **flags.json（json_flag）の新規作成**
   - カスタムフラグを使用するmodは `type: "json_flag"` の定義ファイルが必要
   - `modinfo.json` の `dependencies` にも関係する可能性あり

6. **name フィールド形式の厳格化**
   - `ITEM`, `MONSTER`, `SPELL` 等: 単純文字列 → `{"str_sp": "..."}` 必須
   - `overmap_terrain`, `mutation`, `profession` 等: `{"str_sp": "..."}` → 単純文字列必須

### A2. `rules/common_errors.md` に未反映のエラーを追記

上記6項目に対応するエラーメッセージと解決策を `common_errors.md` に追加：

- `Invalid enum string 'ARMOR_BALLISTIC'`（既存の `remove_armor_bullet.py` 関連）
- `Name is not an object` / `str_sp not supported`（name フィールド形式）
- `missing mandatory member "see_cost"`（overmap_terrain）
- `Invalid or misplaced field name "compare_int"`（EOC）
- `rot_spawn` 形式エラー
- `json_flag` 未定義エラー

### A3. `rules/CORE.md` に `name` フィールド形式のルールを追加

`CORE.md` は「全モデル必読」であるため、最も頻発する `name` フィールド形式の変更について簡潔なルールを追加する（2〜3行）。

## フェーズB: スクリプト改善

### B1. `scripts/convert_item_types.py` — 未対応タイプの追加

CDDA 0.I コアデータ調査結果：`type: "AMMO"` は**完全に廃止**され、すべて `type: "ITEM"` + `subtypes` に統合されている。同様に `TOOL`, `GUN`, `ARMOR` 等もすべて `ITEM` に統合されている。

0.Iで使用されている `subtypes` 一覧（`external/cdda/data/json/items/` から抽出）：
`ARMOR`, `COMESTIBLE`, `TOOL`, `AMMO`, `BOOK`, `GUN`, `MAGAZINE`, `GUNMOD`, `BIONIC_ITEM`, `SEED`, `MILLING`, `PET_ARMOR`, `WHEEL`, `ENGINE`, `BREWABLE`, `ARTIFACT`, `TOOLMOD`, `COMPOSTABLE`

**現在の `TYPE_MAP` で未対応の旧タイプ：**
- `AMMO`, `MAGAZINE`, `GUNMOD`, `BIONIC_ITEM`, `SEED`, `MILLING`, `PET_ARMOR`, `WHEEL`, `ENGINE`, `BREWABLE`, `ARTIFACT`, `TOOLMOD`, `COMPOSTABLE`

**修正:** 上記すべてを `TYPE_MAP` に追加する。ただし、旧modで使用される可能性が高いものを優先：
- `AMMO` → `["AMMO"]`
- `MAGAZINE` → `["MAGAZINE"]`
- `GUNMOD` → `["GUNMOD"]`
- `BIONIC_ITEM` → `["BIONIC_ITEM"]`
- `SEED` → `["SEED"]`
- `TOOLMOD` → `["TOOLMOD"]`
- `GENERIC` はすでに対応済み

### B2. 同様の誤りの有無確認

レビュー内で「コアデータでは `type: "AMMO"` は依然として使用可能」という誤った記述があった。同様に、以下についても0.Iの実態と整合しているか確認する：
- `version_diff.md` の「AMMO タイプの統合」セクションの記述が正確か
- `common_errors.md` の `unrecognized JSON object / type: "AMMO"` エントリの記述が正確か
- その他、0.Iの仕様について「旧バージョンと同様」または「まだ有効」等の記述がないか精査する

## フェーズE: 移植済みmodのGit管理対応

### E1. 配置場所の決定

ユーザー方針：旧modを移植した場合は**変更差分を保存したい** → Git管理対象とする。

**採用方針（選択肢A）:**
- 移植済みmodは `mods/` 配下に配置し、Git管理対象とする
- テスト時: `scripts/link_mod_for_test.sh` または `scripts/copy_mod_for_test.sh` を作成し、`external/cdda/mods/` へ一時的に反映する
- 既存の `external/cdda/mods/Magiclysm_with_Random_Dungeons-0I/` は、テスト用スクリプトで `mods/` からリンクまたはコピーする運用に移行する

### E2. テスト用スクリプトの作成

```bash
# scripts/link_mod_for_test.sh
# 使用例: bash scripts/link_mod_for_test.sh mods/Magiclysm_with_Random_Dungeons-0I
```

- `external/cdda/mods/` にシンボリックリンクを作成（Linux環境）
- Windows環境を考慮する場合は `copy_mod_for_test.sh` も作成

### E3. `.gitignore` の見直し

- `external/cdda/` は現状 `.gitignore` 対象だが、`external/cdda/mods/` 配下に手動配置した移植modが残っている場合、移行後は削除または `.gitignore` に追加の除外ルールが不要か確認
