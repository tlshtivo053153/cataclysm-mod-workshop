# Plan: CDDA Debug Log Error Summarizer

## Goal
Create a Python script that reads a large CDDA `debug.log` file, groups similar errors by kind, counts them, and prints one representative example per group.

## Context
- `debug.log.prev` is ~35,000 lines with ~2,927 ERROR entries.
- Errors are multi-line blocks starting with `HH:MM:SS.mmm ERROR :`.
- Main categories observed:
  1. `src/flexbuffer_json.cpp:353` — "Unread data. Invalid or misplaced field name \"...\" in JSON data" (~2,314)
  2. `src/translation.cpp:232` — "str_sp not supported here" (~521)
  3. `src/text_style_check_reader.cpp:63` — text spacing issues (~91, split into `unnecessary spaces` and `insufficient spaces`)
  4. Backtrace + "Stale game data detected..." (~1)

## Critical Design Points

### A. Block Parsing (Backtrace Handling)
A backtrace error spans two `ERROR` appearances:
1. `ERROR : (error message will follow backtrace)`
2. Several lines later: `(continued from above) ERROR : src/... [func] actual message`
These must be merged into **one block**. The parser must recognize `(continued from above)` lines and append them to the preceding backtrace block instead of treating them as a new block.

### B. Block Boundary Rule
- Start: line matching `^\d{2}:\d{2}:\d{2}\.\d+ ERROR`.
- End: next line matching `^\d{2}:\d{2}:\d{2}\.` (any new timestamped log line: INFO, WARN, ERROR), **unless** that line is `(continued from above) ERROR`.

### C. Signature Extraction (with concrete examples)
Goal: variable parts (timestamps, line numbers, field names, file paths) are normalized so that "the same kind" of error groups together.

1. **Backtrace errors**:
   - Signature = the human-readable sentence on the `(continued from above)` line.
   - Example: `Stale game data detected at FILE, did you overwrite old files? ...`
2. **json-error — `flexbuffer_json.cpp`**:
   - Extract the colored error message line: `<color_white><color_cyan>Unread data. Invalid or misplaced field name "..." in JSON data</color>`
   - Normalize the quoted field name to `"..."`.
   - Signature: `Unread data. Invalid or misplaced field name "..." in JSON data`
3. **json-error — `translation.cpp`**:
   - Signature: `str_sp not supported here`
4. **json-error — `text_style_check_reader.cpp`**:
   - Extract the colored message. There are **two distinct sub-types**:
     - `unnecessary spaces before this location.`
     - `insufficient spaces at this location. ... required, but only ... found.`
   - For the insufficient-spaces variant, normalize the numbers to `...` to keep one group.
   - Signature examples:
     - `unnecessary spaces before this location.`
     - `insufficient spaces at this location. ... required, but only ... found.`
5. **Fallback**: first non-empty line of the block (with timestamp removed).

### D. Existing Codebase Alignment
- Check `scripts/common.py` and existing Python scripts (e.g., `convert_item_types.py`) for shebang, import style, and argparse patterns before writing the new script.
- Keep the script self-contained; only import stdlib modules unless the project already uses a specific CLI library.

## Steps

### 1. Survey Existing Script Style
- Read `scripts/common.py` and one existing Python script to match coding conventions.

### 2. Create `scripts/summarize_debug_log.py`
- **Arguments**:
  - Positional: log file path.
  - Optional: `--output PATH`, `--top N`, `--json`.
- **Parser**:
  - Read line-by-line, accumulate blocks using the boundary rules above.
  - Handle the backtrace merge explicitly.
- **Signature builder**:
  - Detect json-error blocks by the presence of `Json error:`.
  - Extract the colored `<color_cyan>...</color>` message line as the signature.
  - Apply the normalizations listed in **Section C**.
- **Aggregation**: `dict[signature] = {count: int, example: list[str]}`.
- **Output** (default human-readable):
  ```
  ================================================================================
  Count: 2314
  Signature: Unread data. Invalid or misplaced field name "..." in JSON data
  --------------------------------------------------------------------------------
  00:29:43.110 ERROR : src/flexbuffer_json.cpp:353 ...
  Json error: file data/json/monsters/fungus_zombie.json, at line 358, character 16:
  <color_white><color_cyan>Unread data. Invalid or misplaced field name "upgrades" in JSON data</color>
  ... (full block preserved) ...
  ```
  - Sorted by count descending.

### 3. Validation
- Run against `debug.log.prev`.
- Check totals: expected ~2,927 errors.
- Check group counts:
  - `str_sp not supported here` → ~521.
  - `Unread data. Invalid or misplaced field name "..." in JSON data` → ~2,314.
  - `unnecessary spaces ...` + `insufficient spaces ...` → ~91 combined.
  - Backtrace stale-data → 1.
- Ensure the representative example for each group is a **verbatim** copy of the original block.

### 4. Optional: CLI improvements (if time permits)
- `--output` / `-o` to redirect summary to a file.
- `--top N` to limit output to the N most frequent groups.
- `--json` for machine-readable output.

## Success Criteria
- Script finishes on `debug.log.prev` in under one second.
- Summary is concise (likely <10 groups for this log).
- Every group shows an accurate count and one **unmodified** representative example.
- Backtrace-style error is not double-counted.
