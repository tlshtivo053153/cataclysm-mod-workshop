# 技術的負債分析レポート

## A. 破損参照 (Broken References) — 修正優先度: 高

### A1. `pyproject.toml` の存在しないファイル参照
- **場所**: `pyproject.toml:9,44`
- **問題**:

- **影響**: パッケージング失敗、CI/テスト実行不可

### A2. `logs/2026-04-23_Magiclysm...porting.md` の存在しないスクリプト参照

- **影響**: このログを参照した人が混乱する。履歴としての正確性が損なわれる

### A3. `issue.md` の削除済みスクリプト参照
- **場所**: `issue.md:26-27`
- **問題**: 解決済み項目として `scripts/rule_manager.py`, `prompt_builder.py`, `balance_checker.py` が言及されているが、2026-05-19 のリファクタリングでこれらのファイルは削除された。issue.md の記載が実際のコードベースと不一致
- **影響**: issue.md の信頼性低下

## B. コード品質問題 (Code Quality) — 修正優先度: 中

### B1. `main()` 関数の重複
- **影響ファイル**: `convert_item_types.py`, `remove_armor_bullet.py`, `remove_invalid_fields.py`, `revert_translation_errors.py`, `revert_all_translations.py`, `add_activity_level.py`（計6ファイル）
- **問題**: 各スクリプトの `main()` 関数がほぼ同一の10-15行のボイラープレート（`--input`/`--output` ディレクトリ分岐、`backup` 処理、`load_json`/`save_json` 呼び出し）。DRY原則違反
- **修正案**: `common.py` に `run_standard_pipeline()` 関数を追加し、processorだけを渡す形に統一

### B2. `fix_duplicate_ids.py` — ハードコードされた絶対パス
- **場所**: `fix_duplicate_ids.py:6-7,13`
- **問題**:
  - `/home/tlsh/cataclysm/cdda_mod_framework/external/cdda/mods/...` という絶対パスがハードコード
  - プロジェクトルート直下にある孤立したアドホックスクリプトで、再使用性ゼロ
- **修正案**: 削除するか、一般的なスクリプトに書き直して `scripts/` に移動

### B3. `scripts/add_activity_level.py` — Magiclysm特化のハードコード
- **場所**: `scripts/add_activity_level.py:12-21`
- **問題**: `ACTIVITY_MAP` が Magiclysm の `CSC_PSY_MAGI_*` サブカテゴリに特化してハードコードされている。汎用的に使えない
- **修正案**: デフォルトは `DEFAULT_ACTIVITY` のみとし、`ACTIVITY_MAP` は `--config` オプションで JSON/YAML ファイルから読み込むようにする

### B4. `scripts/convert_price.py` — `--output` ディレクトリモード非対応
- **場所**: `scripts/convert_price.py:79-85`
- **問題**: 他のすべての変換スクリプトが `--output` ディレクトリ指定をサポートしているのに、これだけ明示的に拒否している。正規表現置換を使っているため `process_directory()` が使えないが、ファイル単位でコピーするラッパーを書けば対応可能
- **修正案**: `process_directory()` を使うか、同等のファイルコピー + インライン処理ラッパーを追加

### B5. `sys.path.insert` パターンの乱用
- **影響ファイル**: 全 Python スクリプト（`convert_item_types.py`, `add_activity_level.py`, `convert_price.py`, `remove_armor_bullet.py`, `remove_invalid_fields.py`, `revert_translation_errors.py`, `revert_all_translations.py`）
- **問題**: 各ファイルで `sys.path.insert(0, str(Path(__file__).parent))` を実行して `common` をインポートしている。プロジェクトとしてのパッケージ構造がない
- **修正案**: `pyproject.toml` で `scripts/` をパッケージとして設定するか、`pip install -e .` 可能な構成にする

## C. ハウスキーピング問題 (Housekeeping) — 修正優先度: 低

### C1. 空ディレクトリの `.gitkeep` 欠落
- **問題**: `mods/large/`, `mods/medium/`, `mods/seen/`, `mods/unseen/`, `benchmarks/random/` が空のまま `.gitkeep` なし。Git は空ディレクトリを追跡しないため、clone 時にこれらのディレクトリが復元されない
- **修正**: `.gitkeep` を追加

### C2. `scripts/clear_log.sh` — 過剰に小さなラッパー
- **場所**: `scripts/clear_log.sh`（3行）
- **問題**: `check_mods.sh` が既に debug.log クリアを行っている（`check_mods.sh:32`）。このスクリプトは機能が重複しており、独立したファイルとして存在する価値が薄い
- **修正案**: 削除するか、`check_mods.sh` の `--clear-log` オプションとして統合

### C3. `issue.md` の内容が古い
- **場所**: `issue.md` 全体
- **問題**: 言及されている `rule_manager.py`, `prompt_builder.py`, `balance_checker.py` は削除済み。信頼区間/z値やウィンドウサイズのハードコード問題も、それらのスクリプトが削除されたことで無意味になった可能性がある
- **修正案**: 全体を見直し、実際に存在する問題のみに整理

## D. アーキテクチャ観点 (Architecture) — 今後対応

### D1. テスト不在
- **問題**: `pyproject.toml` で `testpaths = ["scripts/tests"]` が指定されているが、テストディレクトリもテストコードも一切存在しない。全スクリプト（JSON変換、翻訳処理、ログパーサー）が無試験

### D2. CI/CD 不在
- **問題**: GitHub Actions や pre-commit hooks がなく、lint/format/validate が手動運用のみ

### D3. `patches/` の大規模バイナリ的データ
- **問題**: パッチセットが合計 ~4.8 MB。Git の履歴が肥大化する。パッチは冪等な変換の生成物であり、再生成可能なはず
- **注意**: これは意図的な判断の可能性があるため、設計判断の確認が必要

### D4. パッケージ構造の欠如
- **問題**: `scripts/` 内のファイルがフラットに並んでおり、Python パッケージとして構造化されていない。`common.py` 以外のモジュール間連携がなく、再利用性が低い
