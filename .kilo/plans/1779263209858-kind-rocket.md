# CDDA Mod Framework 改善計画

## 概要
前回の批判的分析で特定された構造的・運用的・技術的な問題点を修正する。

## 修正項目と手順

### Phase 1: スクリプトの品質・保守性向上（優先度: 高）
1. **PythonスクリプトのCLI引数統一**
   - `add_activity_level.py`, `remove_invalid_fields.py` のハードコードされたパスを除去
   - `argparse` で `--input`, `--output`, `--backup` を標準化
2. **バックアップ機構の導入**
   - 全Python変換スクリプトに、in-place上書き前に `.bak/` へ退避する処理を追加
3. **コードスタイル統一**
   - `pyproject.toml` を作成し、`black` / `ruff` の設定を追加
   - 全Pythonスクリプトを `black` でフォーマット（インデント2→4統一等）
4. **無効フィールドリストの外部化**
   - `rules/invalid_fields.json` を新規作成
   - `remove_invalid_fields.py` がこれを読み込むように変更

### Phase 2: ルールファイルの構造改善（優先度: 高）
5. **ルールファイルの重複解消**
   - `version_diff.md` と `common_errors.md` の重複を整理
   - `common_errors.md` は各エラーの解決策に焦点し、`version_diff.md` への参照リンクを追加
6. **`rules/patterns/` の活用**
   - `.gitkeep` を削除し、実際のパターン例（武器copy-from設計パターン等）を追加

### Phase 3: 検証・テスト自動化の基盤（優先度: 中）
7. **`validate.sh` の強化**
   - 必須フィールド（`id`, `type`, `name` 等）の存在確認を追加
   - `copy-from` で参照するIDが同一mod/依存mod内に存在するかの簡易チェック
8. **`logs/` の構造化**
   - `logs/<mod_name>/<date>.md` 形式への移行
   - 既存ログを整理

### Phase 4: 環境・再現性の担保（優先度: 中） — Phase 1〜2 ではスキップ
9. **`external/cdda/` バージョン固定スクリプト** — 今回はスキップ（ユーザー確認済み: 手動セットアップ、git worktree + symlink を想定）
10. **パッチ管理の改善** — 今回はスキップ

### Phase 5: ドキュメント・構成の整備（優先度: 低）
11. **言語統一**
    - `AGENTS.md` を日本語に翻訳（または日本語ファイルを別途作成）
12. **`mods/` / `benchmarks/` の構成見直し**
    - `mods/` の `seen/unseen` の意図を明確化、または `own/porting/archive` へ再編
    - `benchmarks/` の目的と評価指標を定義
13. **設計書と実装の同期検証（オプション）**
    - `design.md` 内のIDや数値が実際のJSONに存在するかチェックする簡易スクリプト

## 確認事項（確定済み）

1. **言語統一**: `AGENTS.md` は英語のまま。人間向けREADMEは日本語のまま。役割分離はそのまま維持。
2. **Pythonツール導入**: `pyproject.toml` に `black`, `ruff`, `pytest` を追加し、`scripts/setup_venv.sh` も作成する。
3. **`external/cdda/` のセットアップ**: 手動セットアップを想定。git worktree + symlink の運用を想定しているため、自動cloneスクリプトは作成しない。
4. **実施範囲**: Phase 1〜2 のみ実施。Phase 3〜5 は別タスクとする。
